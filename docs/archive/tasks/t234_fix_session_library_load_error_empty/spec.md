## 背景

来源：p058。

`src/renderer/components/session-library/SessionLibrary.tsx` 的 `load_error` 唯一渲染点是被 `visible_sessions.length === 0` 门控的空态分支（`:369-386`）。两个残余缺口：① 中途分页失败时部分数据照常展示且无「加载中断」标识（`set_load_error(true)` 在 `:98`，但非空列表不渲染任何错误提示）；② `load_error=true` 且筛选匹配 0 条时，空态误报「会话列表加载失败」并隐藏「清除筛选」按钮（应区分加载失败与无匹配）。2026-08-07 核实：`:369-386` 逻辑未变，两缺口仍在。

## 契约区

reviewer 判 AC 时只看本区。

### 范围

- 区分空态两种语义：「会话列表加载失败（all 为空）」与「无匹配（all 非空，筛选过滤为空）」。
- 中途分页失败时，在列表上方或相应位置增加「加载中断」提示，不清空已加载数据。

### 非范围

- 不改会话数据加载、分页、筛选的既有逻辑与结果。
- 不改「加载失败」与「无匹配」之外的空态文案行为。

### 验收标准

只写用户或调用方可观察行为，每条可独立验证。普通版本号、底层库和目录结构不作为验收标准；需要长期约束后续工作的技术选择写入 `docs/blueprint/decisions.md`。

需真实部署或人工环境才能验证的条目加 `[deploy]` 前缀，标明 agent 无法自证。

- [x] `load_error=true` 且筛选匹配 0 条时，空态显示「加载失败」语义文案而非「无匹配」，且不隐藏「清除筛选」按钮。
- [x] 中途分页失败且已有部分数据时，列表照常展示并出现「加载中断」提示；失败发生在无数据时，空态显示「加载失败」。
- [x] 无错误且筛选匹配 0 条时，空态显示「没有匹配的会话」并保留「清除筛选」按钮，行为与现状一致。

### 可测试性声明

逐条说明哪些 AC 不可自动测试及原因；全部可测则写「全部 AC 可自动测试」。

- 全部 AC 可自动测试：`tests/unit/renderer/components/session_library/SessionLibrary.test.tsx` 用 mock `getSessions` 构造「分页中途失败」「加载失败 + 筛选 0 条」「正常无匹配」三场景断言文案与按钮。
