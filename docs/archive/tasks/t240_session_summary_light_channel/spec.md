# Task spec

契约区执行期原则上不再改动；确需调整须经用户确认（渲染 review prompt 时脚本会附契约区相对 diff_anchor 的 drift diff 供 reviewer 核对）。上下文区执行期可补。

## 背景

会话库卡片/行的摘要（首条用户消息）经懒加载逐卡片 `sessionHistory.query({limit: 5})` 获取：主进程每次都全量解析整个源文件只为取 5 条消息，一页 50 张卡片 = 50 次全量解析；且每条摘要到达单独 `set_summaries`，触发整表重渲染。另外现状取的是「末 5 条消息中第一条 user」，长会话下并非会话首条 user 消息，与摘要语义（首条用户消息）不符。

## 契约区

reviewer 判 AC 时只看本区。

### 范围

- 主进程提供会话摘要轻量查询：JSONL 类源（claude_code / kimi / grok）从文件头按行扫描，命中首条 user 即停；opencode 走 db 按会话查首条 user 消息；均不做全量提取。
- preload 暴露对应 API；会话库按页批量获取摘要并合批更新渲染。
- 摘要语义修正为会话内首条 user 消息文本（截取 80 字符），无 user 消息为空串。

### 非范围

- 不做生成式 AI 摘要；不改摘要展示位置、样式与缓存 key 语义。
- 不改 token-stats store 结构。

### 验收标准

只写用户或调用方可观察行为，每条可独立验证。普通版本号、底层库和目录结构不作为验收标准；需要长期约束后续工作的技术选择写入 `docs/blueprint/decisions.md`。

需真实部署或人工环境才能验证的条目加 `[deploy]` 前缀，标明 agent 无法自证。

- [ ] 获取单会话摘要不触发该会话的全量提取（文件读取量 / 解析调用次数与消息总数无关，插桩断言）。
- [ ] 摘要内容 = 会话内首条 user 消息文本前 80 字符；无 user 消息时为空串；源文件缺失时为空串且不报错。
- [ ] 一页卡片（50 个）的摘要经批量通道获取，到达后整表重渲染次数有固定小上界。
- [ ] 摘要缓存语义不变：同 key 不重复请求；卡片选择 / 预览 / 打开等交互不变，现有会话库测试保持通过。

### 可测试性声明

逐条说明哪些 AC 不可自动测试及原因；全部可测则写「全部 AC 可自动测试」。

- 全部 AC 可自动测试：临时 fixture + 插桩 + 渲染计数断言。

### 有意不测

已判定不写测试的分支与原因。reviewer 不得据此出 blocking finding。无则写「无」。

- 无

### 测试策略

mock 边界、fixture 来源、断言目标。无特殊约定写「按项目默认」。

- 主进程：fixture 文件分别构造首条 user 在头部 / 深部 / 缺失的场景，断言扫描提前终止与摘要正确；opencode 用临时 db fixture。
- renderer：批量 mock 返回，断言合批渲染次数与同 key 去重。

### 未知契约清单

尚未核实的外部 endpoint、API 形态、数据结构、第三方行为须分类标记；核实后删除标记，改为结论并注明验证方式。无则写「无」。

`UNVERIFIED-BLOCKING`：只有用户或外部环境能核实；核实前 `start` 失败。

`UNVERIFIED-SPIKE`：agent 可在执行期 Step 1 实验核实；未核实前不得进入实现。

裸 `UNVERIFIED` 属歧义格式，门禁失败。

- 无

### 风险与回退

- 风险：摘要语义从「末 5 条中首条 user」修正为「会话首条 user」，展示内容变化属按摘要原意的修正；JSONL 首部连续非 user 行时向后扫描设行数上限，超限回退空串，避免退化为全量读取。
- 回退：恢复 `query({limit: 5})` 通道。
