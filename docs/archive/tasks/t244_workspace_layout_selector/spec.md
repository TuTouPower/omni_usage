# Task spec

契约区执行期原则上不再改动；确需调整须经用户确认（渲染 review prompt 时脚本会附契约区相对 diff_anchor 的 drift diff 供 reviewer 核对）。上下文区执行期可补。

## 背景

工作台的会话排布目前只能通过工具条中间的列数数字按钮切换，不直观。用户希望在「视图」菜单里按当前会话数量直接给出可选的行列排布（如 6 个会话可选 3 列×2 行或 2 列×3 行）。

## 契约区

reviewer 判 AC 时只看本区。

### 范围

- 工作台「视图」下拉菜单中增加会话排布选择区，选项按当前已装入的会话数量生成。
- 选项覆盖（列数×行数语义，行数由会话数与列数推出）：
    - 6 个会话：3 列×2 行、2 列×3 行；
    - 3 个会话：3 列×1 行、2 列（首行 2 个、次行 1 个）；
    - 8 个会话：4 列×2 行、2 列×4 行。
- 其余会话数给出合理的等价列数选项（实现时按同一规则推导：列出能摆下当前会话数的候选列数及其对应行数）。
- 选择某排布后，工作台网格按所选列数排布。

### 非范围

- 不删除工具条中间的列数数字按钮（由后续 task 处理）。
- 不改变单槽位最小列宽与容器宽度不足时的自动降档规则。
- 不改变槽位拖拽换位逻辑。

### 验收标准

只写用户或调用方可观察行为，每条可独立验证。普通版本号、底层库和目录结构不作为验收标准；需要长期约束后续工作的技术选择写入 `docs/blueprint/decisions.md`。

需真实部署或人工环境才能验证的条目加 `[deploy]` 前缀，标明 agent 无法自证。

- [ ] AC1：「视图」菜单中出现排布选择区，选项文本体现列×行（如「3 列 × 2 行」），且选项随当前会话数变化。
- [ ] AC2：装入 6 个会话时，排布选项包含 3 列×2 行 与 2 列×3 行；装入 3 个会话时包含三列与「2+1」两种；装入 8 个会话时包含 4 列×2 行 与 2 列×4 行。
- [ ] AC3：选择某排布后，网格按所选列数渲染（受容器宽度降档规则约束时除外）。
- [ ] AC4：当前生效的排布在菜单中有选中态标识。

### 可测试性声明

逐条说明哪些 AC 不可自动测试及原因；全部可测则写「全部 AC 可自动测试」。

- AC3 中「受容器宽度降档」分支：jsdom 无真实布局宽度，容器宽度相关断言以 `effective_columns` 纯函数测试覆盖，组件级不断言像素排布。

reviewer 判测试覆盖时核对本区；实施期可补。

### 有意不测

已判定不写测试的分支与原因。reviewer 不得据此出 blocking finding。无则写「无」。

- 真实窗口缩放下的像素级排布：由 `effective_columns` 既有测试与人工黑盒覆盖，不在本 task 新增。

### 测试策略

mock 边界、fixture 来源、断言目标。无特殊约定写「按项目默认」。

- 选项生成逻辑抽为纯函数（输入会话数，输出候选排布列表），单测覆盖 3/6/8 及边界会话数。
- 组件级测试：渲染工具条，断言视图菜单中的排布选项与选中态。

### 未知契约清单

尚未核实的外部 endpoint、API 形态、数据结构、第三方行为须分类标记；核实后删除标记，改为结论并注明验证方式。无则写「无」。

`UNVERIFIED-BLOCKING`：只有用户或外部环境能核实；核实前 `start` 失败。

`UNVERIFIED-SPIKE`：agent 可在执行期 Step 1 实验核实；未核实前不得进入实现。

裸 `UNVERIFIED` 属歧义格式，门禁失败。

### 风险与回退

- 风险：排布选项与既有列数状态不同步会导致显示错乱；实现时须让菜单选项与当前布局状态同源。
- 回退：从视图菜单移除排布区即恢复原状。
