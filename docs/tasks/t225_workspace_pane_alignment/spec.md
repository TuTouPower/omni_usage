# Task spec

契约区执行期原则上不再改动；确需调整须经用户确认（渲染 review prompt 时脚本会附契约区相对 diff_anchor 的 drift diff 供 reviewer 核对）。上下文区执行期可补。

## 背景

槽位模型落地后，单个会话面板（pane）仍是旧形态：简单栏头 + user/assistant 纯文本消息行。用户确认面板交互对齐 demo，但消息渲染只加 Markdown、不扩展提取器（不引入 code/diff/tool 分块）。本 task 重做 pane 的头部、消息区、脚部与聚焦/大纲/快捷键交互。

## 契约区

reviewer 判 AC 时只看本区。

### 范围

- pane 头部：顶部 agent 识别色条；agent 徽标（含 model）、会话标题、cwd + `轮数 · tokens · 日期` meta 行；hover 浮现操作：大纲、全选可见、清空选择、聚焦此面板、关闭。
- 消息区：user/assistant 文本按 Markdown 渲染（含 GFM、代码块样式；不渲染原始 HTML）；跨 10 分钟插时间分隔线；滚离底部超过阈值出现「回到底部」按钮；加载时骨架屏。
- 大纲抽屉：pane 内右侧滑出，每条消息一行（角色序号 + 摘要 + 时间），点击滚动定位到对应消息。
- 聚焦模式：单面板铺满工作区，退出后恢复原布局。
- pane 脚部：槽位号 + user/assistant 消息计数统计行。
- 工作台工具条「视图」下拉：显示时间戳、紧凑模式两个开关，作用于全部 pane。
- 快捷键：`1-8` 聚焦对应槽位、`[` `]` 循环切换聚焦、`Esc` 逐层退出（大纲 → 聚焦 → 回到普通态）。
- 保留现有能力：实时推送追加、向上分页（含滚动锚点补偿）、源文件缺失空态、经 URL query 的初始定位。

### 非范围

- 不扩展提取器与消息模型（不引入 code/diff/tool 消息块类型）。
- 不做代码块语法高亮库级渲染（仅 Markdown 代码块样式）。
- 不实现消息勾选/Shift 连选/摘选托盘（后续 task；本 task 的「全选可见/清空选择」按钮只做 UI 挂载，行为随摘选 task 接通——若实现顺序允许可直接留到摘选 task 落地，需在实施笔记说明）。
- 不改槽位 rail、布局切换、picker/recent 弹窗。

### 验收标准

只写用户或调用方可观察行为，每条可独立验证。普通版本号、底层库和目录结构不作为验收标准；需要长期约束后续工作的技术选择写入 `docs/blueprint/decisions.md`。

需真实部署或人工环境才能验证的条目加 `[deploy]` 前缀，标明 agent 无法自证。

- [ ] pane 头部显示 agent 色条、徽标（含 model）、标题、cwd 与 `轮数 · tokens · 日期`；hover 头部浮现大纲/全选可见/清空选择/聚焦/关闭操作。
- [ ] 消息文本按 Markdown 渲染：标题、列表、表格、行内代码、代码块（带样式）正确呈现；会话内容中的 HTML 标签不被当作 HTML 执行（按文本或忽略处理）。
- [ ] 相邻消息时间跨度超 10 分钟时插入时间分隔线。
- [ ] 向上滚动离底超过阈值出现「回到底部」，点击滚回底部；新消息推送到达时若已在底部则自动跟随。
- [ ] 大纲抽屉列出本 pane 全部消息（角色序号 + 摘要 + 时间），点击条目滚动定位。
- [ ] 聚焦模式下单面板铺满工作区；按 `Esc` 或再次点击退出聚焦，恢复原布局。
- [ ] pane 脚部显示槽位号与 user/assistant 消息计数。
- [ ] 「视图」下拉的显示时间戳、紧凑模式开关对所有 pane 即时生效。
- [ ] 快捷键：`1-8` 聚焦对应槽位（有视觉指示）、`[` `]` 循环切换聚焦槽位、`Esc` 按大纲 → 聚焦 → 普通态逐层退出。
- [ ] 实时推送追加、向上分页滚动锚点、源文件缺失空态、初始定位不回归。

### 可测试性声明

逐条说明哪些 AC 不可自动测试及原因；全部可测则写「全部 AC 可自动测试」。

- AC 4 的滚动行为（跟随/回到底部）：jsdom 无真实布局与滚动度量，测状态与阈值判定逻辑；真实滚动效果标 `[deploy]` 目验。
- AC 9 快捷键的全局冲突表现：组合逻辑可测；与系统/输入法实际交互标 `[deploy]` 目验。

## 上下文区

reviewer 判测试覆盖时核对本区；实施期可补。

### 有意不测

已判定不写测试的分支与原因。reviewer 不得据此出 blocking finding。无则写「无」。

- 骨架屏动画时序：纯视觉效果，无行为断言价值。

### 测试策略

mock 边界、fixture 来源、断言目标。无特殊约定写「按项目默认」。

- Markdown 渲染：组件测试覆盖标题/列表/表格/代码块/HTML 转义用例；渲染器选型需为默认不渲染原始 HTML 的安全配置。
- 大纲/聚焦/视图开关/快捷键：组件与状态层测试。
- 不回归项：保留并适配现有 session_history_view、HistoryMessageRow 测试；旧测试语义失效时新增覆盖新语义的测试，旧测试原样保留或整体删除并写明理由。

### 未知契约清单

尚未核实的外部 endpoint、API 形态、数据结构、第三方行为须分类标记；核实后删除标记，改为结论并注明验证方式。无则写「无」。

`UNVERIFIED-BLOCKING`：只有用户或外部环境能核实；核实前 `start` 失败。

`UNVERIFIED-SPIKE`：agent 可在执行期 Step 1 实验核实；未核实前不得进入实现。

裸 `UNVERIFIED` 属歧义格式，门禁失败。

- 项目是否已有 Markdown 渲染依赖（如 react-markdown 等价物）、新增依赖体积与许可：`UNVERIFIED-SPIKE`，执行期读 `package.json` 核实，新增依赖需报用户确认。

### 风险与回退

- 风险：Markdown 渲染引入 XSS 面（会话内容不可信）；渲染长消息性能下降影响滚动与分页。
- 回退：单 commit revert；渲染器禁用原始 HTML 作为硬约束；性能问题可降级为长消息截断渲染。

### 依赖与约束

- 依赖槽位 rail 模型已落地（见 task.md front matter 依赖链）。
- 消息模型不变：`HistoryMessage{role,text,timestamp}`；安全约束：会话文本不可信，禁止 dangerouslySetInnerHTML 直渲。
