# Task spec

契约区执行期原则上不再改动；确需调整须经用户确认（渲染 review prompt 时脚本会附契约区相对 diff_anchor 的 drift diff 供 reviewer 核对）。上下文区执行期可补。

## 背景

代理面板每次切换筛选或图表选项都会重新执行完整数据加载。现有 request id 只阻止旧响应覆盖新状态，无法复用刚查询过的组合，也不会停止或合并重复查询；用户来回切换时反复等待同一结果。

## 契约区

reviewer 判 AC 时只看本区。

### 范围

- 按所有影响查询结果的选项生成稳定 query key，并缓存已经转换为面板状态的数据结果。
- 使用 stale-while-revalidate：命中缓存时立即展示，后台静默校验新数据；缓存缺失时保留当前内容并显示非阻塞加载状态。
- 合并相同 query key 的在途请求，快速连续切换只允许最新选项提交可见状态。
- collector 数据更新时使缓存进入 stale 状态，并静默刷新当前可见查询。
- 将配置别名读取从统计数据加载路径拆出，配置只在初始化与配置变更事件时同步。
- 缓存容量有界，淘汰后可重新查询，不持久化到磁盘。

### 非范围

- 不改变现有 token-stats 查询和 IPC 返回结构。
- 不新增持久化聚合表，不移动 SQLite 查询进程。
- 不改变统计口径、图表视觉样式或用户保存的筛选偏好。

### 验收标准

只写用户或调用方可观察行为，每条可独立验证。普通版本号、底层库和目录结构不作为验收标准；需要长期约束后续工作的技术选择写入 `docs/blueprint/decisions.md`。

需真实部署或人工环境才能验证的条目加 `[deploy]` 前缀，标明 agent 无法自证。

- [ ] AC1：切换到已加载过且仍可用的选项组合时，已有结果立即显示，不出现清空图表或全屏“加载中”。
- [ ] AC2：同一 query key 同时触发多次加载时只执行一套底层查询；所有等待方复用同一结果。
- [ ] AC3：快速连续修改多个选项时，只有最终选项结果进入可见状态，过期请求不能覆盖或清空最终结果。
- [ ] AC4：collector 更新后，当前可见查询在保留旧结果的同时静默刷新；再次访问旧缓存不会永久显示更新前数据。
- [ ] AC5：统计选项切换不再调用配置读取；配置别名在首次打开与配置变更后仍正确应用。
- [ ] AC6：缓存条目数量有明确上限，超过上限会淘汰旧条目；缓存不会随切换组合数量无限增长。

## 上下文区

reviewer 判测试覆盖时核对本区；实施期可补。

### 有意不测

已判定不写测试的分支与原因。reviewer 不得据此出 blocking finding。无则写「无」。

- 不断言缓存命中达到固定毫秒值：测试断言同步展示缓存且不发重复查询，绝对渲染时间由性能基线观察。

### 测试策略

mock 边界、fixture 来源、断言目标。无特殊约定写「按项目默认」。

- 把 query key、缓存、在途请求合并与失效逻辑放在可独立测试边界，使用可控 Promise 验证并发时序。
- renderer 测试模拟来回切换、快速连切、collector 更新和配置广播，断言用户可见图表与 IPC 调用次数。
- 使用假时钟验证 stale 时间和淘汰，不通过真实 sleep 制造时序。

### 风险与回退

- 风险：query key 漏维度导致错误复用；collector 更新和切换竞态导致新结果被旧缓存覆盖；缓存保留大数组导致内存回升。
- 回退：保留无缓存加载入口；回退实现 commit 即恢复原 request id 行为，不涉及持久数据。

### 依赖与约束

- 依赖 P0 性能基线，实施前记录原链路 IPC 次数与重复切换结果。
- renderer 响应配置广播只同步 state，不因广播反向保存配置。
- 并发与缓存失效属于高风险状态管理，使用 full review。
