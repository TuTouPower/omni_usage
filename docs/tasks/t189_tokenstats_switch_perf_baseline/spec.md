# Task spec

契约区执行期原则上不再改动；确需调整须经用户确认（渲染 review prompt 时脚本会附契约区相对 diff_anchor 的 drift diff 供 reviewer 核对）。上下文区执行期可补。

## 背景

代理面板切换 agent、platform、时间范围、metric、x 轴或粒度时，会并发执行多项 SQLite 查询并把结果传入 renderer。现有链路缺少统一性能基线，无法区分 SQL、结果规模、跨进程传输与 renderer 转换各自耗时，也无法量化后续优化收益。

## 契约区

reviewer 判 AC 时只看本区。

### 范围

- 建立可重复运行的代理面板数据加载性能基线，覆盖常用时间范围、筛选和图表组合。
- 报告查询耗时、返回行数、序列化后字节数、renderer 数据转换耗时及整次加载总耗时。
- 提供不含用户数据和密钥的分级合成数据集，覆盖当前常见规模与更高密度规模。
- 为线上链路增加可关联但默认不产生高频噪声的诊断信息，禁止记录原始会话内容、目录、标题和 secret。

### 非范围

- 不改变查询结果、缓存策略、IPC 契约或面板交互。
- 不以固定绝对耗时作为 CI 门禁，避免硬件差异导致不稳定测试。
- 不实施缓存、持久聚合或查询进程隔离。

### 验收标准

只写用户或调用方可观察行为，每条可独立验证。普通版本号、底层库和目录结构不作为验收标准；需要长期约束后续工作的技术选择写入 `docs/blueprint/decisions.md`。

需真实部署或人工环境才能验证的条目加 `[deploy]` 前缀，标明 agent 无法自证。

- [ ] AC1：单条项目命令可生成代理面板加载基线报告，至少覆盖 24h、7d、30d 与 agent/platform 筛选组合。
- [ ] AC2：每份报告包含各数据查询的耗时、返回行数、序列化字节数，以及 renderer 转换和整次加载总耗时；同次加载可通过非敏感标识关联各阶段。
- [ ] AC3：基线工具可生成至少 60 万条 records 的确定性合成数据，重复运行使用相同输入规模和分布，不读取本机真实 token-stats 数据。
- [ ] AC4：诊断输出不含原始 prompt、会话标题、目录、密钥或完整记录内容；正常生产运行默认不产生逐查询高频日志。
- [ ] AC5：自动化测试验证报告 schema、统计字段和合成数据规模，不依赖绝对毫秒阈值判定通过。

### 可测试性声明

逐条说明哪些 AC 不可自动测试及原因；全部可测则写「全部 AC 可自动测试」。

全部 AC 可自动测试。

## 上下文区

reviewer 判测试覆盖时核对本区；实施期可补。

### 有意不测

已判定不写测试的分支与原因。reviewer 不得据此出 blocking finding。无则写「无」。

- 不对不同机器间绝对耗时一致性做断言：硬件、文件系统缓存和 better-sqlite3 ABI 会影响时间值。

### 测试策略

mock 边界、fixture 来源、断言目标。无特殊约定写「按项目默认」。

- 使用临时 SQLite 数据库和固定种子的合成记录，真实执行 store 查询与 renderer 纯转换逻辑。
- 报告测试断言字段完整、单位明确、行数与字节数非负、组合覆盖完整。
- 脱敏测试向数据中注入可识别标记，断言报告与日志不出现原始值。

### 未知契约清单

尚未核实的外部 endpoint、API 形态、数据结构、第三方行为须分类标记；核实后删除标记，改为结论并注明验证方式。无则写「无」。

`UNVERIFIED-BLOCKING`：只有用户或外部环境能核实；核实前 `start` 失败。

`UNVERIFIED-SPIKE`：agent 可在执行期 Step 1 实验核实；未核实前不得进入实现。

裸 `UNVERIFIED` 属歧义格式，门禁失败。

- 可稳定覆盖跨进程序列化阶段的最小基线边界：UNVERIFIED-SPIKE，执行期比较 Electron IPC 测试夹具与离线序列化估算，选择能在 CI 稳定复现且不改变产品行为的方案。

### 风险与回退

- 风险：基线工具自身分配大量对象，污染被测阶段耗时；诊断日志增加产品开销。
- 回退：诊断保持显式启用并可整体关闭；基线工具独立于运行时主路径，可回退实现 commit 而不影响产品数据。

### 依赖与约束

- 无前置依赖。
- 性能报告只作为后续 task 对比基线，CI 仅验证结构与相对规模，不锁定特定硬件耗时。

### Finalization 时更新的 blueprint
