# Task spec

契约区执行期原则上不再改动；确需调整须经用户确认（渲染 review prompt 时脚本会附契约区相对 diff_anchor 的 drift diff 供 reviewer 核对）。上下文区执行期可补。

## 背景

设置窗口是控件密度最高的窗口（分段控件、开关、输入、下拉、文本域、对话框、列表行俱全），同属 globals 蓝体系，紧随用量面板迁移。

## 契约区

reviewer 判 AC 时只看本区。

### 范围

- 设置窗口（`SettingsView` 全部分区）样式迁移到 ui 组件库 + 语义 token。
- 全部现存用户选项原样保留：五档强调色、用量条样式（细线/胶囊）、主题三档、各自绘控件（下拉、文本域、密钥输入）等。
- 账户管理相关对话框、上下文菜单迁移到统一配方。
- 迁移完成后删除本窗口专属手写 CSS 类，并确认无残留引用。

### 非范围

- 不改设置项的存取逻辑、config schema、IPC。
- 不动其它窗口（t270/t272/t273 各自处理）。
- 不改 web 版（t274 统一核对）。

### 验收标准

只写用户或调用方可观察行为，每条可独立验证。普通版本号、底层库和目录结构不作为验收标准；需要长期约束后续工作的技术选择写入 `docs/blueprint/decisions.md`。

需真实部署或人工环境才能验证的条目加 `[deploy]` 前缀，标明 agent 无法自证。

- [ ] 设置窗口全部现存功能行为不变：各分区渲染、设置读写、账户增删改与对话框流程、密钥明文回填与脱敏规则。
- [ ] 五档强调色、用量条样式、主题三档等全部用户可选项逐项保留可用。
- [ ] 窗口在明暗主题下渲染正确，组件内无 `dark:` 分支。
- [ ] 本窗口专属手写 CSS 类已删除且无残留引用（grep 可证）。
- [ ] 视觉与迁移前逐屏对照无意外差异，符合 DESIGN.md。[deploy]

### 可测试性声明

逐条说明哪些 AC 不可自动测试及原因；全部可测则写「全部 AC 可自动测试」。

- AC 5：视觉对照属人工验证，agent 无法自证；其余经现有测试与黑盒验证。

## 上下文区

reviewer 判测试覆盖时核对本区；实施期可补。

### 有意不测

已判定不写测试的分支与原因。reviewer 不得据此出 blocking finding。无则写「无」。

- 像素级视觉回归：靠人工对照迁移前后截图。

### 测试策略

mock 边界、fixture 来源、断言目标。无特殊约定写「按项目默认」。

- 行为回归以现有设置窗口测试为准；样式断言按新语义类名改写，逻辑断言不动。

### 未知契约清单

尚未核实的外部 endpoint、API 形态、数据结构、第三方行为须分类标记；核实后删除标记，改为结论并注明验证方式。无则写「无」。

`UNVERIFIED-BLOCKING`：只有用户或外部环境能核实；核实前 `start` 失败。

`UNVERIFIED-SPIKE`：agent 可在执行期 Step 1 实验核实；未核实前不得进入实现。

裸 `UNVERIFIED` 属歧义格式，门禁失败。

- 无

### 风险与回退

- 风险：自绘下拉/开关等控件的 DOM 结构变化导致现有测试与快捷键/焦点行为回归。
- 回退：单 commit，revert 即恢复。
