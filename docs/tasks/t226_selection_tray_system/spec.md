# Task spec

契约区执行期原则上不再改动；确需调整须经用户确认（渲染 review prompt 时脚本会附契约区相对 diff_anchor 的 drift diff 供 reviewer 核对）。上下文区执行期可补。

## 背景

用户确认做完整摘选系统：跨会话消息摘选 + 底部托盘 + 三种格式复制，对齐 demo。当前会话窗口只有勾选消息 + 单一 Markdown 复制（`build_copy_markdown`）。本 task 落地选择状态、选择交互与托盘。

## 契约区

reviewer 判 AC 时只看本区。

### 范围

- 选择状态 store：`会话 → 已选消息集合`，跨页签（工作台/会话库）保留；每会话维护 Shift 连选锚点。
- 消息选择交互：消息行左侧选择列，hover 浮现 checkbox；选中态有明确视觉标识；支持点选与 Shift 范围连选。
- 底部摘选托盘：按会话分组排列片段 chip（agent 缩写 + 角色序号 + 摘要 + token 估算 + 单条移除）；空态收成细条，有内容时展开；拖上沿可调高（有上限）；右侧显示片段数与总 tokens、格式下拉（Markdown / 纯文本 / 按会话分组）、「复制」「清空」。
- 复制格式：Markdown、纯文本、按会话分组三种，均含角色、agent 名、时间戳标题信息。
- 顶栏摘选计数徽标：与托盘同源，显示已选片段总数。
- 快捷键：`Space` 选中/取消悬停消息、`Ctrl+Shift+C` 复制托盘内容。
- 替换旧的勾选 + 单一 Markdown 复制路径（`build_copy_markdown` 由新格式模块取代或重构）。

### 非范围

- 不做导出到文件（只写剪贴板）。
- 不做 demo 的飞入动画等纯装饰动效。
- 不改 pane 头部/大纲/聚焦（前一 task）；「全选可见/清空选择」按钮行为在本 task 接通。
- 不做会话库视图（后续 task），但选择 store 需按跨页签共享设计。

### 验收标准

只写用户或调用方可观察行为，每条可独立验证。普通版本号、底层库和目录结构不作为验收标准；需要长期约束后续工作的技术选择写入 `docs/blueprint/decisions.md`。

需真实部署或人工环境才能验证的条目加 `[deploy]` 前缀，标明 agent 无法自证。

- [ ] 消息行 hover 浮现选择框，点击选中/取消；选中消息有明确视觉标识。
- [ ] 按住 Shift 点击可选中锚点到当前消息的范围（每个会话独立锚点）。
- [ ] 底部托盘按会话分组显示已选片段 chip（agent 缩写 + 角色序号 + 摘要 + token 估算），单条可移除；显示片段总数与总 tokens。
- [ ] 托盘空态收成细条，有内容时展开；拖上沿可在下限与上限之间调高。
- [ ] 托盘提供三种复制格式（Markdown / 纯文本 / 按会话分组），复制结果含角色、agent 名、时间戳信息；「清空」清除全部已选。
- [ ] 顶栏显示已选片段计数徽标，与托盘状态同源；切换到会话库页签再切回，已选状态保留。
- [ ] `Space` 选中/取消当前 hover 的消息；`Ctrl+Shift+C` 复制托盘内容。
- [ ] pane 头部「全选可见」选中本 pane 当前已加载的全部消息，「清空选择」清除本 pane 已选。
- [ ] 旧的单一 Markdown 复制入口被新托盘取代，不出现两套并存。

### 可测试性声明

逐条说明哪些 AC 不可自动测试及原因；全部可测则写「全部 AC 可自动测试」。

- AC 4 拖高手势：测高度状态上下限逻辑；真实拖拽标 `[deploy]` 目验。
- AC 5/7 写剪贴板：测格式化输出文本；真实剪贴板写入标 `[deploy]` 目验（沿用现有复制测试的 mock 方式）。

### 有意不测

已判定不写测试的分支与原因。reviewer 不得据此出 blocking finding。无则写「无」。

### 测试策略

mock 边界、fixture 来源、断言目标。无特殊约定写「按项目默认」。

- 选择 store：纯单元测试（点选/Shift 连选/按会话清除/全清/跨页签保留）。
- 三种格式生成：纯函数测试，断言角色/agent/时间戳与分组结构；取代旧 `build_copy_markdown` 的测试按 TDD 规则新增新语义覆盖，旧测试整体删除时在实施笔记写明理由。
- 托盘组件：renderer 组件测试，mock 剪贴板。

### 未知契约清单

尚未核实的外部 endpoint、API 形态、数据结构、第三方行为须分类标记；核实后删除标记，改为结论并注明验证方式。无则写「无」。

`UNVERIFIED-BLOCKING`：只有用户或外部环境能核实；核实前 `start` 失败。

`UNVERIFIED-SPIKE`：agent 可在执行期 Step 1 实验核实；未核实前不得进入实现。

裸 `UNVERIFIED` 属歧义格式，门禁失败。

- 无

### 风险与回退

- 风险：选择状态与消息分页/实时推送交互（未加载的消息不在「全选可见」范围；推送新消息不改变已选集合语义）；新旧复制路径并存遗漏。
- 回退：单 commit revert；旧复制路径测试保留至新路径覆盖后删除。

### 依赖与约束

- 依赖 pane 交互已落地（见 task.md front matter 依赖链）。
- 「全选可见」只覆盖当前已加载进内存的消息，不含未分页加载的历史（与 demo 语义一致）。
