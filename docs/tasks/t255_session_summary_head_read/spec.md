# Task spec

契约区执行期原则上不再改动；确需调整须经用户确认（渲染 review prompt 时脚本会附契约区相对 diff_anchor 的 drift diff 供 reviewer 核对）。上下文区执行期可补。

## 背景

用户反馈会话面板/会话库首次打开仍卡。调查结论：摘要链路名为「轻量」实为整文件读——`extract_claude_code_first_user`（`claude-code-extractor.ts:54-57`）注释声称只读前部少量行，实际第一行就 `readFileSync` 读整个文件再只解析前 1000 行；claude 单会话文件可达数十 MB，首屏 50 个会话各读一遍全文件，WSL UNC 路径进一步放大延迟。

## 契约区

reviewer 判 AC 时只看本区。

### 范围

- 各来源的「首条用户消息」摘要提取改为限量头部读取：单个会话文件的读取字节数有明确上限，不再整文件读入内存。
- 头部读取窗口内未找到用户消息时的行为有明确定义（回退策略或空摘要），不产生错误与界面异常。

### 非范围

- 不改变摘要的展示位置、样式与刷新时机。
- 不改变单会话消息列表的加载方式（整量提取 + 分页维持现状）。
- 不动会话文件定位逻辑（由另一 task 处理）。

### 验收标准

只写用户或调用方可观察行为，每条可独立验证。普通版本号、底层库和目录结构不作为验收标准；需要长期约束后续工作的技术选择写入 `docs/blueprint/decisions.md`。

需真实部署或人工环境才能验证的条目加 `[deploy]` 前缀，标明 agent 无法自证。

- [ ] AC1：各来源会话的摘要（首条用户消息）显示内容与现状一致。
- [ ] AC2：生成单个会话摘要时读取的字节数不超过明确上限，与文件总大小解耦（测试中可断言：大文件 fixture 的摘要读取量有上界，远小于文件大小）。
- [ ] AC3：头部窗口内找不到用户消息的文件按定义行为处理（回退或空摘要），不抛错、不阻塞其他会话摘要。
- [ ] AC4：现有测试与 e2e 全部通过，无回归。

### 可测试性声明

逐条说明哪些 AC 不可自动测试及原因；全部可测则写「全部 AC 可自动测试」。

全部 AC 可自动测试。

## 上下文区

reviewer 判测试覆盖时核对本区；实施期可补。

### 有意不测

已判定不写测试的分支与原因。reviewer 不得据此出 blocking finding。无则写「无」。

- 真实 WSL UNC 大文件的延迟改善量级：无法在测试环境模拟；以读取字节数上限断言代替延迟测量。

### 测试策略

mock 边界、fixture 来源、断言目标。无特殊约定写「按项目默认」。

- tmp 文件 fixture：构造首条用户消息在头部窗口内/外、文件超上限大小、空文件、损坏首行等用例。
- fs 读取边界用 spy 断言读取字节数上限。
- 摘要正确性：与现状提取结果对比（同一 fixture 两种实现输出一致）。

### 未知契约清单

尚未核实的外部 endpoint、API 形态、数据结构、第三方行为须分类标记；核实后删除标记，改为结论并注明验证方式。无则写「无」。

`UNVERIFIED-BLOCKING`：只有用户或外部环境能核实；核实前 `start` 失败。

`UNVERIFIED-SPIKE`：agent 可在执行期 Step 1 实验核实；未核实前不得进入实现。

裸 `UNVERIFIED` 属歧义格式，门禁失败。

- 各来源真实会话文件中首条用户消息出现在头部窗口（如 64KB）内的比例：`UNVERIFIED-SPIKE`，执行期对本机真实会话文件采样统计；比例不足时窗口大小或回退策略需相应调整并在实施笔记记录。

### 风险与回退

- 风险：头部窗口过小导致部分会话摘要丢失（首条用户消息位置靠后）；回退策略选择不当重新引入整文件读。
- 回退：单 commit revert；无持久化状态，无副作用残留。

### 依赖与约束

- 依赖 t254（定位入口稳定后摘要链路随之稳定）；与 t256 同触摘要 IPC 链路，按 t254 → t255 → t256 顺序串行执行。

### Finalization 时更新的 blueprint

- 无（行为与现状一致，仅读取方式变化）。
