# Task spec

契约区执行期原则上不再改动；确需调整须经用户确认（渲染 review prompt 时脚本会附契约区相对 diff_anchor 的 drift diff 供 reviewer 核对）。上下文区执行期可补。

## 背景

会话窗口（工作台/会话库壳）右上角的主题切换按钮是独立主题（localStorage 存储），用户要求主题跟随软件全局设置，该按钮不再需要；其左侧的摘选托盘按钮无点击行为、疑似未生效，一并移除。

## 契约区

reviewer 判 AC 时只看本区。

### 范围

- 移除会话窗口顶栏的主题切换按钮（太阳/月亮图标）。
- 移除会话窗口顶栏的摘选托盘按钮（layers 图标，无 onClick 的未生效按钮）。
- 会话窗口主题改为跟随软件全局主题设置，不再使用会话窗口独立的主题存储。

### 非范围

- 不移除顶栏的「用量面板」「代理面板」两个跳转按钮。
- 不改动工作台底部的摘选托盘面板（`SelectionTray`）本身。
- 不改动主面板/设置中的全局主题切换入口。

### 验收标准

只写用户或调用方可观察行为，每条可独立验证。普通版本号、底层库和目录结构不作为验收标准；需要长期约束后续工作的技术选择写入 `docs/blueprint/decisions.md`。

需真实部署或人工环境才能验证的条目加 `[deploy]` 前缀，标明 agent 无法自证。

- [ ] AC1：会话窗口顶栏不再出现主题切换按钮与摘选托盘按钮。
- [ ] AC2：在主面板设置中切换全局浅色/暗色主题后，重新打开（或已打开的）会话窗口呈现相同主题。
- [ ] AC3：会话窗口内不再写入或读取会话窗口独立的主题 localStorage 键（`omni_session_theme`）。

### 可测试性声明

逐条说明哪些 AC 不可自动测试及原因；全部可测则写「全部 AC 可自动测试」。

- AC2：跨窗口主题联动依赖真实应用环境，自动测试覆盖「主题来源改为全局主题」这一代码路径；端到端联动以黑盒/人工验证补充。

### 测试策略

mock 边界、fixture 来源、断言目标。无特殊约定写「按项目默认」。

- 组件级测试：渲染会话壳，断言顶栏无两个被移除按钮。
- 主题来源：mock 全局主题读取路径，断言会话窗口 `data-theme` 与全局主题一致，且不再写 `omni_session_theme`。

### 未知契约清单

尚未核实的外部 endpoint、API 形态、数据结构、第三方行为须分类标记；核实后删除标记，改为结论并注明验证方式。无则写「无」。

`UNVERIFIED-BLOCKING`：只有用户或外部环境能核实；核实前 `start` 失败。

`UNVERIFIED-SPIKE`：agent 可在执行期 Step 1 实验核实；未核实前不得进入实现。

裸 `UNVERIFIED` 属歧义格式，门禁失败。

- 会话窗口读取全局主题的通道（全局 config.theme 如何到达会话窗口 renderer）：UNVERIFIED-SPIKE，执行期查主面板 `src/renderer/lib/theme.ts` 与设置持久化路径后确定复用方式。

### 风险与回退

- 风险：全局主题读取通道若与主面板不一致，会话窗口可能出现主题错误；已打开窗口的实时联动若未接入，需要 reopen 才生效（AC2 允许 reopen 生效）。
- 回退：恢复两个按钮与独立主题存储逻辑。
