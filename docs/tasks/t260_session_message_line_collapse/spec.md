# Task spec

契约区执行期原则上不再改动；确需调整须经用户确认（渲染 review prompt 时脚本会附契约区相对 diff_anchor 的 drift diff 供 reviewer 核对）。上下文区执行期可补。

## 背景

来源：用户提出（2026-08-07）。会话面板消息列表（`SessionPane` 内 `VirtualMessageList` + `PaneMessageRow`，内容经 `MarkdownMessage` 渲染）当前完整渲染每条消息，长消息占满视口，浏览会话时扫读困难。用户要求所有消息默认只显示一行，超出内容折叠，附折叠按钮，点击后展开。

## 契约区

reviewer 判 AC 时只看本区。

### 范围

- 会话面板（工作台 SessionPane）消息列表中的所有消息默认单行显示，超出一行的内容折叠不可见。
- 内容超出一行的消息显示展开按钮；点击展开显示完整内容，再次点击恢复单行折叠。
- 内容不超一行的消息不显示展开按钮。

### 非范围

- 不改变消息选择、多选、滚动跟随（新消息底部跟随、prepend 补偿）等既有行为。
- 不改 Markdown 渲染本身与消息数据链路。
- 不动会话库、侧边栏与 pane 头部元信息（另有 task）。

### 验收标准

只写用户或调用方可观察行为，每条可独立验证。普通版本号、底层库和目录结构不作为验收标准；需要长期约束后续工作的技术选择写入 `docs/blueprint/decisions.md`。

需真实部署或人工环境才能验证的条目加 `[deploy]` 前缀，标明 agent 无法自证。

- [ ] AC1：内容超出一行的消息默认只呈现第一行，其余内容不可见，且该消息行上呈现展开按钮；内容不超一行的消息不呈现展开按钮。
- [ ] AC2：点击展开按钮后该消息完整显示；再次点击恢复单行折叠。各消息的折叠/展开状态互不影响。
- [ ] AC3：展开/折叠后消息选择状态保持，列表滚动位置不发生跳动错乱（虚拟列表在行高变化后仍正确渲染）。
- [ ] AC4：现有测试与 e2e 全部通过，无回归。

### 可测试性声明

逐条说明哪些 AC 不可自动测试及原因；全部可测则写「全部 AC 可自动测试」。

全部 AC 可自动测试（组件测试构造长短消息断言折叠态与按钮；AC3 用组件测试断言选择状态保持与列表重渲染）。

## 上下文区

reviewer 判测试覆盖时核对本区；实施期可补。

### 有意不测

已判定不写测试的分支与原因。reviewer 不得据此出 blocking finding。无则写「无」。

- 无

### 测试策略

mock 边界、fixture 来源、断言目标。无特殊约定写「按项目默认」。

- 组件级：PaneMessageRow 构造单行/多行消息，断言折叠按钮有无、展开后全文可见、再折叠恢复。
- 虚拟列表行高变化：构造折叠→展开序列断言不抛错、选中状态保持。

### 未知契约清单

尚未核实的外部 endpoint、API 形态、数据结构、第三方行为须分类标记；核实后删除标记，改为结论并注明验证方式。无则写「无」。

`UNVERIFIED-BLOCKING`：只有用户或外部环境能核实；核实前 `start` 失败。

`UNVERIFIED-SPIKE`：agent 可在执行期 Step 1 实验核实；未核实前不得进入实现。

裸 `UNVERIFIED` 属歧义格式，门禁失败。

- `VirtualMessageList` 的行高机制对动态行高（折叠/展开）的支持方式：`UNVERIFIED-SPIKE`，执行期 Step 1 核实虚拟列表是固定行高还是测量行高；固定行高需先改造为可测高或在展开时重测，方案在实施笔记记录。

### 风险与回退

- 风险：虚拟列表若假定固定行高，展开/折叠可能引起渲染错乱或滚动跳动；单行截断对代码块/表格等 Markdown 结构的视觉破坏（截断行内出现不完整标记属预期，以纯文本截断或 CSS 截断方案在实施时定）。
- 回退：单 commit revert。
