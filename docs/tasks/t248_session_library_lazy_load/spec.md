# Task spec

契约区执行期原则上不再改动；确需调整须经用户确认（渲染 review prompt 时脚本会附契约区相对 diff_anchor 的 drift diff 供 reviewer 核对）。上下文区执行期可补。

## 背景

会话库面板打开时循环分页把 SQLite 中全部会话拉进渲染进程（每页 500，直至拉完），再对首屏 50 个会话批量读源文件取摘要。会话多时长面板长时间空白、主进程被同步查询占用，用户感知明显卡顿。需要改为按需加载：首屏只取一页，统计走聚合查询，搜索走后端过滤。

## 契约区

reviewer 判 AC 时只看本区。

### 范围

- 会话库首屏加载：打开会话库页签时只请求第一页会话（50 条，按当前排序），立即渲染，不再循环拉取全部会话。
- 头部统计（会话数 / Agent 数 / tokens 总量）：改为独立的后端聚合查询（SQL COUNT / SUM），不依赖全量列表。
- 「加载更多」：点击时按当前筛选与排序增量拉取下一页并追加渲染。
- 标题 / 路径 / 会话 ID 搜索与 Agent / 日期筛选：改为后端 SQL 过滤（`TOKEN_STATS_SESSIONS` 已有过滤参数），不再要求全部会话在渲染进程内存中。
- 首条消息摘要：只对当前可见会话发起批量请求（维持现状语义，但候选集从「全量内存列表」变为「当前已加载页」）。
- 「包含消息内容」搜索：触发时对当前筛选候选集做后端内容扫描（候选集由后端按筛选条件确定，不依赖渲染进程全量列表）。

### 非范围

- 不改变会话库的视觉布局、排序选项、选择/预览/打开交互。
- 不改动工作台与最近会话弹窗的加载逻辑。
- 不改动 token-stats collector 与各端 reader。
- 不做虚拟滚动（分页「加载更多」已满足当前规模）。

### 验收标准

只写用户或调用方可观察行为，每条可独立验证。普通版本号、底层库和目录结构不作为验收标准；需要长期约束后续工作的技术选择写入 `docs/blueprint/decisions.md`。

需真实部署或人工环境才能验证的条目加 `[deploy]` 前缀，标明 agent 无法自证。

- [ ] AC1：打开会话库页签时，首屏会话列表只经过一次分页请求（limit=50）即渲染；全程不存在「循环拉取直至全部会话加载完成」的行为。
- [ ] AC2：头部统计（N 个会话 · M 个 Agent · X tokens）与全量数据一致，且在首屏列表渲染前后均可独立显示（统计请求与列表请求互不阻塞）。
- [ ] AC3：点击「加载更多」后追加渲染下一页（按当前筛选/排序），重复点击直至无更多时按钮消失。
- [ ] AC4：输入标题/路径/会话 ID 关键词、选择 Agent、设置日期范围后，列表结果与全量内存过滤的结果一致（由后端 SQL 过滤返回）。
- [ ] AC5：勾选「包含消息内容」搜索时，命中集合与现状（对全部候选会话做内容扫描）一致，且不要求渲染进程预先持有全部会话。
- [ ] AC6：摘要请求只对当前已加载且可见的会话发起；切换筛选/排序后未加载摘要的新可见会话会触发新的批量摘要请求。

### 可测试性声明

逐条说明哪些 AC 不可自动测试及原因；全部可测则写「全部 AC 可自动测试」。

- AC1 中「卡顿消失」的主观性能感受不可自动断言；自动测试断言请求次数与分页形态，性能改善以该结构性证据支撑。

## 上下文区

reviewer 判测试覆盖时核对本区；实施期可补。

### 有意不测

已判定不写测试的分支与原因。reviewer 不得据此出 blocking finding。无则写「无」。

- 真实大数据量下的渲染帧率：依赖真实环境，以黑盒/人工验证补充，不写自动化性能测试。

### 测试策略

mock 边界、fixture 来源、断言目标。无特殊约定写「按项目默认」。

- 后端聚合统计：store 层新增统计查询（COUNT / SUM / COUNT DISTINCT source）单测，fixture 用内存 SQLite。
- 后端过滤分页：`query_sessions` 既有过滤参数补测（search / sources / 日期交集 + limit/offset 组合）。
- 渲染进程：mock `tokenStats.getSessions` 与统计 IPC，断言首屏一次请求、加载更多追加、筛选变化重置分页；mock `sessionHistory.searchContent` 断言内容搜索候选不依赖全量列表。
- 摘要：mock `sessionHistory.summaries`，断言仅对可见会话发起。

### 未知契约清单

尚未核实的外部 endpoint、API 形态、数据结构、第三方行为须分类标记；核实后删除标记，改为结论并注明验证方式。无则写「无」。

`UNVERIFIED-BLOCKING`：只有用户或外部环境能核实；核实前 `start` 失败。

`UNVERIFIED-SPIKE`：agent 可在执行期 Step 1 实验核实；未核实前不得进入实现。

裸 `UNVERIFIED` 属歧义格式，门禁失败。

- 「包含消息内容」搜索的候选集在后端按筛选条件确定时的规模上限与超时策略（候选可能达数千个源文件）：UNVERIFIED-SPIKE，执行期以真实数据量评估是否需要分批/进度反馈，必要时在上下文区补充约束。
- 统计聚合查询是否复用现有 dashboard 查询通道或新增 IPC：UNVERIFIED-SPIKE，执行期核对 `TOKEN_STATS_DASHBOARD` 与 store 现有聚合能力后确定。

### 风险与回退

- 风险：搜索/筛选迁到后端后，与既有内存过滤语义（标题/路径/ID 的 LIKE 口径、日期交集口径）不一致会导致结果差异；内容搜索候选集过大时后端扫描耗时可能回退体验。
- 回退：恢复全量拉取与内存过滤路径（保留原实现分支，按开关回退或 git revert）。

### 依赖与约束

- 无前置 task 依赖。
- 性能敏感路径（首屏）不得在渲染进程持有全量会话列表。

### Finalization 时更新的 blueprint

- `docs/blueprint/architecture.md`：会话库数据加载由全量内存模型改为分页 + 后端过滤模型（如该文件有对应描述则同步）。
