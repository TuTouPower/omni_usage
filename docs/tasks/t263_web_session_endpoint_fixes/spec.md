## 背景

web 端会话相关链路存在三个缺陷：

1. 跨面板打开会话丢目标。web 端从用量面板会话表触发打开会话时，web shim 先同步向已订阅的焦点监听器分发目标位置，再切换 hash 路由；会话面板按路由懒挂载，此时尚未挂载、无订阅者，目标位置被丢弃。而初始位置的兜底逻辑只读 URL 查询参数，web shim 从不写查询参数，兜底失效，最终跳到空工作台。桌面端打开会话自带路由查询参数，无此问题。
2. 会话检索端点缺参数时全量枚举。`GET /v1/sessionHistory` 缺 `source`/`env` 参数时回退为分页拉取全部会话再做首个 id 匹配，开销随总会话数线性增长，且多个来源存在相同 id 时有歧义。该回退只为兼容 id-only 调用方，web 端正常查询恒透传 `source`/`env`。
3. web 端内容搜索取消缺口。渲染层已有防抖与过期结果丢弃，但取消信号未传入搜索调用；web shim 经独立 POST 发搜索请求，本身不可取消；服务端处理搜索时不接收中止信号（底层服务已支持），也无客户端断连中止逻辑。连续搜索时前序请求持续扫盘，造成并发堆积。桌面 IPC 路径已有按窗口取消作对照。

## 契约区

reviewer 判 AC 时只看本区。

### 范围

- web 端 `sessionHistory.open` 把目标会话位置可靠传递到会话面板（编码进 URL 或暂存回放，具体方案实施期定）。
- 移除 `GET /v1/sessionHistory` 缺 `source`/`env` 时的 id-only 全量枚举回退（或加 bound 限制），并同步调整断言旧行为的测试。
- web 端内容搜索全链路取消：渲染层取消信号传入请求，服务端随客户端断连中止扫描。

### 非范围

- 桌面 IPC 搜索路径。
- 会话检索端点的访问鉴权（自用场景不做 token-gate）。
- 服务端搜索结果去重合并。

### 验收标准

只写用户或调用方可观察行为，每条可独立验证。普通版本号、底层库和目录结构不作为验收标准；需要长期约束后续工作的技术选择写入 `docs/blueprint/decisions.md`。

需真实部署或人工环境才能验证的条目加 `[deploy]` 前缀，标明 agent 无法自证。

- [ ] AC1：web 端从用量面板会话表打开会话，跳转到会话面板并定位到目标会话。
- [ ] AC2：web 端在会话面板内互跳打开会话仍正常定位；桌面端打开会话行为不回归。
- [ ] AC3：`GET /v1/sessionHistory` 缺 `source`/`env` 时不再全量枚举会话，按实施选择返回参数错误或受限结果；带完整 `source`/`env` 的正常查询不受影响。
- [ ] AC4：web 端连续触发内容搜索时，前序搜索请求被取消；客户端断开后服务端中止对应扫描，不产生并发扫盘堆积。
- [ ] AC5：相关单元测试与集成测试（含按新语义调整后的）全部通过。
