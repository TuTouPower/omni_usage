## 背景

会话路径索引的持久化当前采用「每次变更即全量序列化 + 同步写盘（临时文件 + 原子改名）」。一次索引 miss 的解析过程会多次触发该全量写：解析前校验失败删除条目时写一次，扫描命中回填时再写一次，扫描未命中且键不存在时即使索引内容未变也会做一次纯浪费的全量写。

首开面板时会批量解析全部可见会话（约 50 个），索引冷时序列化规模为 O(N²)，且同步 I/O 直接阻塞主进程 event loop。活跃会话的 mtime 高频变化使索引条目频繁失效，每次打开都会 miss，触发重扫并再次全量写盘。原子写保证索引损坏可容忍（可回退全目录扫描重建），写失败仅告警，这为合并落盘提供了安全基础。

## 契约区

reviewer 判 AC 时只看本区。

### 范围

- 消除单次 miss-resolve 内的重复全量写：单次 miss 解析过程合并为至多一次索引落盘。
- 消除扫描未命中且索引内容未变时的纯浪费写盘。
- 批量解析窗口内的落盘批间合并（debounce / flush 等具体机制执行期实验确定），使批量冷会话解析的落盘次数显著小于会话数。

### 非范围

- 全目录扫描本身的性能优化。
- 索引文件格式变更。

### 验收标准

只写用户或调用方可观察行为，每条可独立验证。普通版本号、底层库和目录结构不作为验收标准；需要长期约束后续工作的技术选择写入 `docs/blueprint/decisions.md`。

需真实部署或人工环境才能验证的条目加 `[deploy]` 前缀，标明 agent 无法自证。

- [ ] 单次 miss-resolve 至多触发一次索引写盘；扫描未命中且不改变索引内容时不写盘。
- [ ] 批量 resolve N 个冷会话（索引冷）时，索引写盘次数显著小于 N，验证落盘批间合并生效。
- [ ] 索引持久性可观测语义不弱化：进程正常退出后，索引文件包含全部已 resolve 条目的最新内容。
- [ ] 进程崩溃导致未落盘条目丢失属于可接受行为：下次打开时回退全目录扫描重建索引，功能正常（权衡说明见上下文区「有意不测」）。
- [ ] 既有 session-path-index 与 session-locator 测试按新落盘语义调整后全部通过，调整理由写入实施笔记。

### 可测试性声明

逐条说明哪些 AC 不可自动测试及原因；全部可测则写「全部 AC 可自动测试」。

全部 AC 可自动测试。AC 1/2/3 以写盘次数计数与索引文件内容断言验证；AC 4 通过删除索引文件后回退扫描重建的既有路径验证；AC 5 由单元测试套件全绿验证。

### 有意不测

已判定不写测试的分支与原因。reviewer 不得据此出 blocking finding。无则写「无」。

- 崩溃瞬间未落盘条目丢失的场景：属有意接受的权衡。原子写保证已落盘内容不损坏，丢失的条目由下次打开时全目录扫描重建，恢复路径已由既有测试覆盖；不构造崩溃注入测试。

### 测试策略

mock 边界、fixture 来源、断言目标。无特殊约定写「按项目默认」。

- 既有测试存在语义锁：tests/unit/main/core/session-history/session-path-index.test.ts:93 在 resolve 同步返回后立即以 existsSync 断言索引文件存在，:104-116 在条目失效后同步断言索引已修正。若批间合并引入异步落盘，这两条断言语义需调整为「flush 后落盘」或改用写盘次数计数断言，调整理由写入实施笔记。
- 以写盘次数计数断言替代或补充「立即 existsSync」断言：对写盘函数做 spy/stub 计数，验证单次 miss 至多一次写、未命中且内容不变时零次写。
- 批量场景构造 N 个冷会话 fixture（索引为空或全失效），批量 resolve 后断言写盘次数显著小于 N，且最终索引文件包含全部 N 个条目。
- 进程正常退出前落盘保证的验证：触发解析后执行退出前 flush 路径，断言索引文件含全部已 resolve 条目。

### 未知契约清单

尚未核实的外部 endpoint、API 形态、数据结构、第三方行为须分类标记；核实后删除标记，改为结论并注明验证方式。无则写「无」。

`UNVERIFIED-SPIKE`：agent 可在执行期 Step 1 实验核实；未核实前不得进入实现。

### 风险与回退

- 风险：引入异步落盘后，flush 时机与进程退出前落盘保证处理不当会造成已 resolve 条目丢失或退出时索引过旧；debounce 窗口参数不当可能使批量场景退化为逐次写盘。
- 回退：恢复逐次全量写盘实现；原子写与回退扫描重建机制保持不变，数据安全不受影响。
