# Task spec

契约区执行期原则上不再改动；确需调整须经用户确认（渲染 review prompt 时脚本会附契约区相对 diff_anchor 的 drift diff 供 reviewer 核对）。上下文区执行期可补。

## 背景

会话窗口外壳基座落地后，工作台页签内仍是旧的 6 栏平铺模型（超位弹窗勾选关栏、「最近 6 条」批量打开）。用户确认对齐 demo 的槽位模型：8 个槽位移至左侧 rail、可拖拽换位、布局 1/2/3/4/6/8 切换、网格按宽度自动降档、超位直接 toast 拒绝。本 task 替换工作台的槽位容器与打开会话的入口交互。

## 契约区

reviewer 判 AC 时只看本区。

### 范围

- 工作台槽位状态模型：固定 8 个槽位，槽位顺序即网格顺序；支持指派、移除、换位、清空。
- 左侧 SessionRail：占用槽位显示 agent 识别色左条 + 徽标 + 标题 + `轮数 · tokens`；空槽位显示虚线占位；可折叠为窄条；拖拽换位（顺序同步到网格）；底部「添加会话」入口。
- 面板网格：按当前布局数（1/2/3/4/6/8）排列已占用槽位；容器宽度不足时列数自动降档。
- 工作台工具条：左侧「最近会话」「清空」；居中布局切换器（1/2/3/4/6/8）。
- SessionPickerModal：搜索（标题/路径，元信息范围）+ agent 筛选页签（带计数）+ 会话行列表；已打开的会话标「已打开」；点行把会话装入目标槽位。
- RecentSessionsModal：全部会话按日期倒序多选（上限 8，选择顺序角标），快捷「最近 2/4/8 个」，确认后清空并替换全部槽位。
- 超位行为：槽位已满时再打开/装入会话，toast 提示拒绝，不替换任何已有槽位；移除旧的栏满弹窗交互与工具栏「最近 6 条」按钮。
- 全空空态：无占用槽位时显示引导（去会话库 / 打开最近会话）。
- 入口重接：从会话明细表「打开历史」、托盘菜单、其它面板跳转会话窗口时，会话装入工作台槽位（窗口未开则先开窗）。

### 非范围

- 不改单个会话面板（pane）内部的消息渲染、头部操作、大纲、聚焦模式（后续 task）。
- 不实现摘选托盘与消息选择交互。
- 不实现会话库视图内容。
- 不动槽位内消息的实时推送与分页机制本身（仅挂载方式随槽位模型调整）。

### 验收标准

只写用户或调用方可观察行为，每条可独立验证。普通版本号、底层库和目录结构不作为验收标准；需要长期约束后续工作的技术选择写入 `docs/blueprint/decisions.md`。

需真实部署或人工环境才能验证的条目加 `[deploy]` 前缀，标明 agent 无法自证。

- [ ] 工作台左侧显示槽位 rail：占用槽位显示 agent 色左条、徽标、标题与 `轮数 · tokens`；空槽位显示虚线占位；rail 可折叠/展开。
- [ ] rail 内拖拽槽位可换位，网格中面板顺序同步变化。
- [ ] 布局切换器在 1/2/3/4/6/8 间切换，网格按选择重排；窗口宽度不足时列数自动降档。
- [ ] 点击空槽位或「添加会话」打开会话选择弹窗：可按标题/路径搜索、按 agent 筛选（带计数）、已打开的会话有「已打开」标记；点选会话后装入目标槽位并展示其消息。
- [ ] 「最近会话」打开多选弹窗：按日期倒序、上限 8、有快捷「最近 2/4/8 个」；确认后清空并替换全部槽位。
- [ ] 8 个槽位占满后再通过任何入口打开会话，toast 提示且已有槽位不变。
- [ ] 从会话明细表勾选「打开历史」、托盘菜单「会话面板」、其它面板跳转入口打开会话窗口时，目标会话装入工作台槽位；窗口已开则聚焦并装入。
- [ ] 全部槽位为空时显示引导空态（含去会话库、打开最近会话入口）。
- [ ] 旧交互不存在：栏满弹窗、「最近 6 条」按钮。
- [ ] 装入槽位的会话保持实时更新与历史分页能力不回归。

### 可测试性声明

逐条说明哪些 AC 不可自动测试及原因；全部可测则写「全部 AC 可自动测试」。

- AC 3 的「自动降档」与 AC 4 的布局重排：依赖容器宽度与 ResizeObserver，jsdom 下只能以注入宽度的方式测判定逻辑；真实窗口下的降档效果标 `[deploy]` 由黑盒目验兜底。
- AC 2 拖拽换位：测状态层换位逻辑；真实拖拽手势标 `[deploy]` 目验。

## 上下文区

reviewer 判测试覆盖时核对本区；实施期可补。

### 有意不测

已判定不写测试的分支与原因。reviewer 不得据此出 blocking finding。无则写「无」。

- 拖拽手势本身（指针事件序列）：jsdom 无法真实模拟 dnd 交互，测 store 层 move 语义即可。

### 测试策略

mock 边界、fixture 来源、断言目标。无特殊约定写「按项目默认」。

- 槽位 store：纯单元测试（assign/remove/move/clear、超位拒绝）。
- rail/网格/弹窗组件：renderer 组件测试，mock preload API 与 sessions provider 数据。
- 入口重接：复用现有 session_table/tray_menu/route_api 测试并补槽位装入断言。

### 未知契约清单

尚未核实的外部 endpoint、API 形态、数据结构、第三方行为须分类标记；核实后删除标记，改为结论并注明验证方式。无则写「无」。

`UNVERIFIED-BLOCKING`：只有用户或外部环境能核实；核实前 `start` 失败。

`UNVERIFIED-SPIKE`：agent 可在执行期 Step 1 实验核实；未核实前不得进入实现。

裸 `UNVERIFIED` 属歧义格式，门禁失败。

- `recent_sessions` 数据源（tokenStatsStore.query_sessions 桥接）返回的会话是否带标题/日期/轮数/token 等 picker 与 rail 所需字段：`UNVERIFIED-SPIKE`，执行期读 main 侧桥接代码与类型定义核实。

### 风险与回退

- 风险：槽位模型替换影响订阅生命周期（槽位移除=退订、窗口销毁注销全部）；入口重接漏掉某个跳转路径导致打开落空。
- 回退：单 commit revert；订阅服务单测（subscription-service、history-window-controller）作安全网。

### 依赖与约束

- 依赖会话窗口外壳基座已落地（见 task.md front matter 依赖链）。
- 沿用现有 sessionHistory IPC 通道组；槽位装满即拒，不引入排队或替换策略。
