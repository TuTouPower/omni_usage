## 硬约束（安全红线，最高优先级）

- **对所有会话 transcript 源文件（Claude/Kimi/Grok JSONL、OpenCode SQLite、scan-state、任何用户数据目录内容）全程只读**。不增、不改、不删、不移位、不压缩、不加锁写。打开文件只以只读模式（`fs.read` / `better-sqlite3 { readonly: true }`）。
- **「关闭会话」/「清空全部」/「淘汰」等一切操作只作用于前端界面与主进程内存中的订阅/watcher 状态**，即停止刷新、移除栏位、释放 watcher 句柄。绝不触碰磁盘上的会话文件。
- 调试复现产生的任何文件只写 `.scratch/`，不得写回 transcript 所在目录。

## 背景事实（探索结论）

- 代理面板 = `TokenStatsView`（窗口 route `agent`），「会话明细」表 = `SessionTable.tsx`。会话行目前单击无任何行为、无选中机制。
- 支持 4 类 agent：`claude_code`（JSONL，`~/.claude/projects/**`，含 subagent 文件 `agent-*.jsonl`）、`opencode`（SQLite，`~/.local/share/opencode/opencode.db`）、`kimi_code`（JSONL，win+wsl 双环境）、`grok`（JSONL，仅 WSL）。会话行已有 `identity_key`（`source|env|session_id`），能唯一定位一个会话。
- 现有 reader 只提取 token 计数与首条用户文本（作标题），正文解析逻辑需要新写，但各 reader 已封装了文件定位、增量扫描、env 处理，可复用。
- 新窗口有成熟模式：`WINDOW_CONFIGS` + route + singleton controller（参照 agent 窗口 `create_agent_window_controller`）。
- token-stats 采集进程独立，每 10 分钟轮询一次写 SQLite 并广播 `TOKEN_STATS_UPDATED`。会话历史的实时刷新与这套管线解耦（数据源不同）。
- renderer 现有依赖无 markdown 渲染库；无现成 toast/复制组件。

## Q2 / 消息内容提取范围A

从原始 transcript 提取哪些内容渲染。以 claude_code JSONL 为例，一行可能是：user 文本、assistant 文本、tool_use、tool_result、system 行、thinking 块。

- **A（推荐）：仅 user 文本 + assistant 文本**。tool 调用/结果、system、thinking 一律不显示。四端裁剪规则统一，实现最少，直接命中「看到用户输入和 Agent 输出」的字面需求。代价：看不到 Agent 做了什么操作，上下文可能断裂。
- **B：A + tool 摘要**。tool_use 折叠成一行摘要（如 `Bash: pnpm test`），tool_result 不显示。更接近真实对话，但四端（尤其 opencode part 结构）各写一套摘要规则，工作量约翻倍。
- **C：全部内容**。信息过载，不推荐。

## Q3 / 窗口形态B（已选 B：单窗口内分栏平铺）

- **A：单一独立窗口，内部 tab 展示多会话**。顶部 tab 栏切换，最多 6 个 tab。
- **B（已选）：单窗口内分栏平铺**。多个会话并排同时可见，每栏一个会话（栏头：agent + 标题 + 关闭按钮 ×）。窗口顶部工具栏有「清空全部」按钮，点击关闭所有栏。布局自适应：1~2 会话纵向整行排列，3~6 会话两列网格（3=2+1，4=2×2，5=2+2+1，6=2×3）；窗口尺寸不足时每栏内容区独立滚动。选中/复制操作按栏独立。
- **C：每会话一个独立窗口**。最多 6 个窗口。窗口管理复杂，不推荐。

## Q4 / 超过 6 个会话的处理（已选：弹窗由用户选择关闭）

打开第 7 个会话时不自动淘汰，改为弹出模态对话框：列出当前 6 个会话（agent + 标题 + 打开时间），每项带关闭按钮（或勾选 + 底部「关闭选中」），用户手动关闭至少一个后新会话才入栏；用户也可以点「取消」放弃打开新会话。

- **已选：模态弹窗，用户自己决定关哪个**。无自动淘汰，不存在误顶。
- 细节确认（无异议即默认）：
    - 弹窗里必须至少关闭 1 个才能确认；关满后新会话立即入栏。
    - 批量打开（明细表多选 7 个）时弹窗同样生效：先列出需腾出的位数（7-6=1 位起），用户关够位数后全部新会话按序入栏；位数 = 新会话数 − 剩余空位。
    - 弹窗中被关闭栏的已选消息随之丢弃（仅前端状态，不动文件）。
- **被淘汰的旧方案（弃用）**：FIFO 自动淘汰最早打开栏 / 最久未交互淘汰。

## Q5 / 刷新机制A + 5s 兜底

- **A（推荐）：主进程 watcher 推送**。主进程对每个打开的会话监听 transcript 源文件（fs watch；opencode 为 db 文件，sqlite 多写者下退化为 2s 轮询该会话的 mtime），检测到变化→解析增量→`send` 给历史窗口。真实时、零无效读取。增量解析复用现有 reader 的 offset/mtime 机制。claude_code 增量按字节 offset 读 JSONL 尾部即可，四端都已有类似实现基础。
- **B：renderer 定时拉取，5s**。实现最简单（复用 query IPC），5 秒延迟对「实时」感知可接受；代价是每 5s 全量重拉 6 个会话的消息（需配合按 offset/timestamp 增量拉取，否则大会话每次重传全量）。
- **C：renderer 定时拉取，2s**。感知更接近实时，无效请求翻倍。
- 折中：A 的 watcher 做主动推送 + renderer 侧 5s 兜底拉一次（防 watch 丢事件，尤其 WSL 路径经 9P 协议 fs watch 不可靠）。推荐 **A + 5s 兜底**。
- WSL 注意：kimi/grok 的 transcript 在 WSL 文件系统内，Windows 侧 `\\wsl.localhost\...` 路径的 fs.watch 不可靠，这些源直接用 2s 轮询 mtime。

## Q6 / 只有打开窗口时才高频刷新

用户已明确「只有历史窗口打开的会话才频繁刷新，其他按原来」。落实口径：

- **A（推荐）**：历史窗口打开会话 → renderer 通过 IPC 向主进程**注册订阅**（source, env, session_id）；主进程为该会话启动 watcher/轮询；tab 关闭或窗口关闭 → 注销订阅、停 watcher。token-stats 采集进程 10 分钟轮询**完全不动**。会话明细表本身也不因历史窗口打开而加快刷新。
- 无其他合理选项，此条主要确认理解一致。

## Q7 / 会话明细表的多选交互A

- **A（推荐）：行首加 checkbox 列 + 工具栏「打开历史」按钮**。勾选 ≥1 行后按钮可用，点击批量在历史窗口打开（超 6 按 Q4 淘汰）。单击行 = 直接打开该会话（不改动 checkbox 选中态）。checkbox 列最明确，不与排序/分页交互冲突。
- **B：Ctrl/Shift + 单击多选，双击打开**。无视觉提示，发现性差；且「单击打开」与「Ctrl+单击多选」并存时单击语义冲突（单击既是打开又是选择）。
- 右键菜单（打开历史）作为补充可选项，默认不做。

## Q8 / 消息记录的选择交互A（补充：跨栏选择）

- **A（推荐）：每条消息 hover 显示 checkbox（或常驻左侧窄列），点击选中/取消**。选中集合跨刷新保留（按消息 id 记录）。交互确定性强，不依赖快捷键。
- **跨栏选择（用户补充）**：允许在多个栏各自选中消息。每栏栏头显示「已选 N 条」；**复制按钮放到窗口顶部工具栏**（不再随栏），全局一个，汇总所有栏的选中（如「复制 12 条」），点击一次复制全部。各栏仍保留「全选本栏」「清除本栏选择」。
- **B：Ctrl/Shift 点选文本块**。更接近聊天软件，但实现复杂且与文本拖选复制冲突，不推荐。

## Q9 / 复制输出的格式B（已选 B：Markdown；补充：跨栏合并 + 会话隔离）

复制所有栏选中消息，一次生成 Markdown 文本。结构：按会话分节，节内消息按时间升序，角色用粗体小标题：

```markdown
## 会话：fix login bug（claude-code · 2026-08-04）

**用户**

消息内容……

**Claude**

回复内容……

---

## 会话：refactor store（opencode · 2026-08-05）

**用户**

……
```

- **已选 B：Markdown 格式**。会话节标题含会话标题 + agent + 日期，节间 `---` 分隔作会话隔离标记；消息间空行，角色 `**用户**` / `**Agent 名**`。
- **跨栏合并（用户补充）**：多个栏有选中时按「栏打开顺序」依次输出各会话节；单栏有选中则只输出一节。
- **与 Q11 的连带关系（需知悉）**：界面显示为纯文本（Q11-A），复制输出为 Markdown，两者不一致——复制时从主进程返回的原始消息文本重新生成 Markdown，不从 DOM 取显示文本。接受「复制≠显示」。
- **被淘汰（弃用）**：A 带角色前缀纯文本 / C 无前缀裸文本。

## Q10 / 复制反馈A

- **A（推荐）：顶部工具栏复制按钮短暂变为「已复制 ✓」1.5s 后恢复**。项目内无 toast 组件，不为此引入 toast 系统。
- **B：新增全局 toast 组件**。更通用但超本需求范围。

## Q11 / assistant 输出的渲染方式A

agent 输出含 markdown（代码块、列表、标题等）：

- **A（推荐）：纯文本展示 + `<pre>` 风格保留换行/缩进**。零新依赖，复制内容=显示内容，所见即所得。代码块显示原始围栏文本。
- **B：引入轻量 markdown 渲染**（如 marked，~40KB）。代码块高亮/排版好，但新增依赖、CSP 需放行（项目有严格 `csp.ts`）、复制时需另生成纯文本版本（显示与复制两份内容）。
- 倾向 A：本窗口核心动作是「复制原文」，不是阅读体验。

## Q12 / 历史会话与新开窗口的行为A

打开一个磁盘上已被压缩/删除 transcript 的会话（会话明细表来自 SQLite，记录还在，但原始文件可能没了）：

- **A（推荐）：栏照常打开，内容区显示空态「该会话的原始记录文件不存在或已删除」**。不阻断其他栏。
- **B：打开前预检，文件不存在则拒绝打开并提示**。多一次 IO，且文件可能打开后才被删，仍要处理 A 的空态，故 A 足够。

## Q13 / claude_code 的 subagent 消息A

claude_code 会话含主 transcript + subagent 文件（`agent-*.jsonl`），现有明细表把 subagent token 合并进主会话统计。

- **A（推荐）：只显示主 transcript 的 user/assistant 消息**。subagent 输出本就通过主会话的 tool_result/summary 间接体现（虽然 Q2-A 下 tool_result 不显示）。语义=「用户视角的对话」。
- **B：subagent 消息按时间穿插进主对话流**，标注来源（如 `[subagent: Explore]`）。信息更全，但时间对齐与来源标注增加复杂度。
- **C：独立开关/折叠区显示 subagent**。默认收起。介于两者之间。

## Q16 / Web 版（usageboard-web）是否支持A

- **A（推荐）：本期不做 Web 版**。会话历史依赖主进程直接读本地文件，Web 版需新 HTTP 端点 + SSE 推送；需求只提桌面窗口。local-api 端点留作后续 task。

## Q17 / 长会话的性能上限A

单会话消息量级可达数千条（claude 长会话 JSONL 数 MB）。

- **A（推荐）：窗口内虚拟滚动 + 主进程解析结果按消息分页推送**（初始加载最近 200 条，向上滚动加载更早；新增消息追加尾部）。复制只对已选消息生效，选择状态按消息 id 存 renderer。
- **B：全量加载**。数千条消息 DOM 全渲染会卡，不推荐。

## 需求边界确认（无异议即默认成立）

- 复制支持跨栏合并：多栏各自选中后，顶部工具栏一次复制，输出按会话分节（`## 会话：…` + `---` 隔离）。
- 历史窗口关闭 = 全部订阅注销；重开窗口不恢复之前的栏（会话从明细表重新打开）。
- 窗口顶部工具栏：「清空全部」按钮（关闭所有栏，不弹确认，直接执行）+ 全局复制按钮（显示总选中数）+ 已打开会话计数（如 3/6）。
- 分栏平铺窗口默认 1400×860（6 栏两列网格下单栏约 690×410，可读下限）；允许用户拖大拖小，栏内容区独立滚动。
- 会话明细表的分页（每页 100）不变；checkbox 选中态仅当前页有效，翻页清空（跨页暂存选中会让「打开历史」语义变模糊）。
- 不显示 thinking、system、tool_result（随 Q2-A）；消息时间戳显示到分钟，悬停显示完整时间。
