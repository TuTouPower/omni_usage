# Task spec

契约区执行期原则上不再改动；确需调整须经用户确认（渲染 review prompt 时脚本会附契约区相对 diff_anchor 的 drift diff 供 reviewer 核对）。上下文区执行期可补。

## 背景

会话库「包含消息内容」搜索在每次输入变化时对全部候选会话**串行** `await` 逐会话 `sessionHistory.query`（每次主进程都全量解析对应源文件），无输入防抖；旧查询不取消仅丢弃结果，IPC 调用在主进程排队堆积；结果合并 `filter` 套 `some` 为 O(n²)。数百个会话时每敲一键都引发一轮全量扫描，搜索框直接卡死，是搜索场景卡顿的根因。

## 契约区

reviewer 判 AC 时只看本区。

### 范围

- 主进程新增批量内容搜索能力：一次调用接收候选会话定位集合与关键词，返回命中会话键集合；内部复用提取缓存、限制同时解析的源文件数，并支持协作式中断（新查询到达使旧查询停止解析）。
- preload 暴露对应 API。
- 会话库：搜索输入防抖；切换关键词 / 取消勾选时作废旧任务；命中合并改 Set；「搜索中」提示保持。
- 结果保持并集语义：元信息命中 ∪ 正文命中。

### 非范围

- 不改元信息搜索（标题 / 路径 / 会话 ID）逻辑；不改搜索 UI 布局。
- 不建全文索引或引入搜索引擎；不改分页协议。
- 提取缓存本身由前置 task 落地，本 task 只复用。

### 验收标准

只写用户或调用方可观察行为，每条可独立验证。普通版本号、底层库和目录结构不作为验收标准；需要长期约束后续工作的技术选择写入 `docs/blueprint/decisions.md`。

需真实部署或人工环境才能验证的条目加 `[deploy]` 前缀，标明 agent 无法自证。

- [ ] 连续输入时仅在停顿后触发一次搜索：防抖窗口内多次键入只产生一次批量调用。
- [ ] 一次内容搜索对全部候选会话只产生一次 renderer→main 调用，返回命中集合。
- [ ] 搜索进行中修改关键词或取消勾选时，旧批量任务停止解析、不再占用主进程，最终展示结果以最新输入为准。
- [ ] 结果集合 = 元信息命中 ∪ 正文命中，与现状逐会话搜索的结果一致（同 fixture 对比）。
- [ ] 主进程同时解析的源文件数有固定上界（插桩断言不超过上限）。

### 可测试性声明

逐条说明哪些 AC 不可自动测试及原因；全部可测则写「全部 AC 可自动测试」。

- 全部 AC 可自动测试：fake timers 断言防抖；mock IPC 计数；临时 fixture 会话文件断言结果一致与并发上界。

## 上下文区

reviewer 判测试覆盖时核对本区；实施期可补。

### 有意不测

已判定不写测试的分支与原因。reviewer 不得据此出 blocking finding。无则写「无」。

- 真实数千会话下的搜索耗时绝对值：环境相关，以调用次数、并发上界与中断断言替代。

### 测试策略

mock 边界、fixture 来源、断言目标。无特殊约定写「按项目默认」。

- 主进程：临时目录构造多会话 JSONL fixture，断言批量接口返回命中键集与逐会话旧逻辑结果一致；插桩并发计数与中断标志。
- renderer：fake timers 断言防抖后调用次数；搜索中切换关键词断言旧结果被丢弃、最新输入结果上屏。

### 未知契约清单

尚未核实的外部 endpoint、API 形态、数据结构、第三方行为须分类标记；核实后删除标记，改为结论并注明验证方式。无则写「无」。

`UNVERIFIED-BLOCKING`：只有用户或外部环境能核实；核实前 `start` 失败。

`UNVERIFIED-SPIKE`：agent 可在执行期 Step 1 实验核实；未核实前不得进入实现。

裸 `UNVERIFIED` 属歧义格式，门禁失败。

- 无

### 风险与回退

- 风险：批量接口参数体积（候选定位集合上千）带来 IPC 序列化开销；以 source/env/日期预过滤收敛候选集。
- 回退：删除批量接口，恢复逐会话 query，仅保留防抖与 Set 合并。

### 依赖与约束

- 依赖：会话历史查询缓存已落地（批量接口复用其缓存供数，避免批量搜索退化为逐文件全量解析）。
- 约束：与会话摘要轻量通道、memo 化、SessionLibrary 文件拆分 task 同文件（`SessionLibrary.tsx` / IPC / preload），须串行（conflicts_with 登记）。
