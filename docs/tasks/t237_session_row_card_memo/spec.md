# Task spec

契约区执行期原则上不再改动；确需调整须经用户确认（渲染 review prompt 时脚本会附契约区相对 diff_anchor 的 drift diff 供 reviewer 核对）。上下文区执行期可补。

## 背景

会话历史渲染层有两个互相叠加的卡顿来源：

1. `PaneMessageRow` / `MarkdownMessage`（react-markdown，单条解析成本高）与 `SessionCard` / `SessionRow` 均未 memo 化，回调全为内联闭包。勾选单条消息 → selection_store 变更 → `WorkspaceView` 整树重渲染 → 所有面板所有消息行重渲染且 markdown 全量重解析；新消息推送/兜底返回 → 整列 markdown 重解析；会话库每张卡片摘要到达单独 `set_summaries` → 一页 50 次整表重渲染。表现为「点一下就卡一下」。
2. 会话面板消息区把所有已加载消息全量 DOM 渲染：每页 200 条可无限向上翻页，DOM 与 markdown 实例随消息数无界增长。`layout.ts` 注释声称「虚拟滚动分页页大小」，实际只有分页、没有虚拟化。几千条消息 × 多面板时滚动与任何触发重渲染的操作都卡顿。

## 契约区

reviewer 判 AC 时只看本区。

### 范围

- `PaneMessageRow` / `MarkdownMessage` memo 化；选中态以稳定 boolean props 传入，行级回调稳定化。
- `SessionCard` / `SessionRow` memo 化与回调稳定化；摘要状态更新合批，一页卡片摘要到达不再逐条触发整表重渲染。
- `SessionPane` 消息区窗口化渲染：DOM 仅保留可视窗口加缓冲区，渲染行数不随已加载消息数线性增长。
- 保持既有交互语义：向上翻页 prepend 的滚动补偿、at-bottom 新消息跟随、回到底部按钮、大纲定位（含可视区外目标）、消息选择 / Shift 连选 / 悬停。
- 窗口化索引计算抽纯函数，便于单测。

### 非范围

- 不改分页协议、主进程与 IPC；不改加载页大小（200/页）。
- 不替换 markdown 渲染器，不改 `MarkdownMessage` 的 props 契约（text 进、渲染出）。
- 不改选择 / 悬停 / 复制 / 预览 / 打开等行为语义与样式；不改面板头部 / 大纲 / 脚部结构。

### 验收标准

只写用户或调用方可观察行为，每条可独立验证。普通版本号、底层库和目录结构不作为验收标准；需要长期约束后续工作的技术选择写入 `docs/blueprint/decisions.md`。

需真实部署或人工环境才能验证的条目加 `[deploy]` 前缀，标明 agent 无法自证。

- [ ] 勾选/取消单条消息时，仅该行重渲染，同面板其他消息行不重渲染（渲染计数断言）。
- [ ] 新消息推送到列尾时，既有消息行不触发 markdown 重解析（渲染计数或 props 引用相等断言）。
- [ ] 会话库一张卡片摘要到达时，其余已渲染卡片不重渲染；一页摘要批量到达时整表重渲染次数有固定小上界。
- [ ] 加载多页（≥3 页）后，消息区 DOM 行数有固定上界（可视窗口 + 缓冲区），与已加载总条数解耦。
- [ ] 向上翻页 prepend 时可视内容不跳动（滚动补偿语义保持）；「回到底部」与 at-bottom 新消息跟随行为不变。
- [ ] 大纲点击定位可视区外的消息时，能跳转并使目标行渲染可见。
- [ ] 消息选中 / Shift 连选 / 悬停 Space 选中、卡片选择 / 预览 / 打开行为不变；现有面板与会话库测试保持通过（语义失效的旧测试按项目 TDD 规则处理：新增覆盖新语义的测试，旧测试整体删除并写明理由）。

### 可测试性声明

逐条说明哪些 AC 不可自动测试及原因；全部可测则写「全部 AC 可自动测试」。

- memo 相关 AC（1/2/3）可自动测试：testing-library + 渲染计数探测组件断言重渲染范围。
- DOM 上界 / 滚动补偿 / 大纲定位（4/5/6）依赖真实布局（scrollHeight / clientHeight），jsdom 无法自证：窗口化纯函数（索引计算、缓冲边界）由单测覆盖；DOM 行数上界与滚动行为走 e2e（Playwright）断言。
- AC7 可自动测试（沿用现有测试）。

## 上下文区

reviewer 判测试覆盖时核对本区；实施期可补。

### 有意不测

已判定不写测试的分支与原因。reviewer 不得据此出 blocking finding。无则写「无」。

- 极端行高差异（单条超长代码块数千 px）下的滚动平滑度：体验向指标，人工抽查，不写自动断言。

### 测试策略

mock 边界、fixture 来源、断言目标。无特殊约定写「按项目默认」。

- 渲染计数：用带渲染计数器的探测包装（profiler 或计数子组件）断言重渲染范围；交互行为沿用现有 pane / library 测试，不改其语义。
- 窗口化计算抽纯函数单测：给定 scrollTop / 行高数据 / 消息数，断言渲染窗口索引与缓冲边界。
- e2e：开面板加载多页，统计消息行 DOM 数有上界；翻页后断言首屏消息锚点稳定；大纲跳转可视区外目标断言该行渲染可见。

### 未知契约清单

尚未核实的外部 endpoint、API 形态、数据结构、第三方行为须分类标记；核实后删除标记，改为结论并注明验证方式。无则写「无」。

`UNVERIFIED-BLOCKING`：只有用户或外部环境能核实；核实前 `start` 失败。

`UNVERIFIED-SPIKE`：agent 可在执行期 Step 1 实验核实；未核实前不得进入实现。

裸 `UNVERIFIED` 属歧义格式，门禁失败。

- 可变行高下的窗口化方案（markdown 消息高度不一，定高假设不成立；测量/估计策略与滚动补偿的交互）：UNVERIFIED-SPIKE，执行期 Step 1 用真实会话数据 spike 验证候选方案（自研窗口化 vs 现成虚拟列表库）后定实现。

### 风险与回退

- 风险：memo 化后 props 比较掩盖应更新的场景（如选中态漏传）导致 UI 不刷新；以交互测试兜底。
- 风险：窗口化下滚动补偿、大纲定位、选择锚点回归；以 e2e 关键路径覆盖兜底。
- 回退：去掉 memo 包装恢复每次重渲染；还原全量渲染（保留现有分页）。

### 依赖与约束

- 无前置 task 依赖。
- 约束：与超行数文件拆分、会话库查询通道优化等同文件改动（`SessionPane.tsx` / `SessionLibrary.tsx` / `WorkspaceView.tsx`）须串行（conflicts_with 登记）。

### Finalization 时更新的 blueprint

- `docs/blueprint/decisions.md`：消息区虚拟化方案与行高策略（选型有长期约束时记录）。
